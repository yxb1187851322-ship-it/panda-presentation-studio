# 阅读设计案例的方法

参考案例首先是一套设计表达。学习它如何把问题变为可以讨论的方案，再独立判断哪些内容可迁移到当前任务。原稿的文化概念、照片、平面与结论不能直接换个名字就当作新项目成果。

首次需要实际方法例子时读[已提炼的方法](learned-patterns.md)。它给出来源范围、操作和失效条件，不替代当前项目分析。

## 读完整关系，不只选漂亮页

先识别全稿章节和实际可读范围，再沿一条关键关系连续读：项目条件与目标、概念来源、概念的具体转译、平面或空间操作、材料/构件/光的落实、效果与校核。至少打开关键转折页的真实画面；扫描文档提取到零散文字不等于读到了正文。

优先追踪“中间怎样转译”：例如概念中的疏密如何落在构件序列，内向或开放如何落在平面，仪式感如何由入口与停留位置体现。只找到概念词和最终效果图，不能声称完整推演已被证实；中间缺口要留下。

页码相邻、颜色相同只是寻找关系的线索。若无文案或图示说明因果，记为“可解释的对应”，不要写成已证实的作者意图。成稿是对外叙事，不能反推出真实设计过程的先后、团队争议或用户访谈。

## 一张案例方法卡

按实际信息填，不强补每格：

| 内容 | 要回答的问题 |
| --- | --- |
| 原问题与条件 | 谁的项目？什么场地/使用/品牌诉求？源页在哪里？ |
| 概念回应 | 原稿提出什么概念，回应哪部分问题？有没有直接依据？ |
| 转译动作 | 概念如何变成组织、尺度、虚实、开口、构件或其他设计动作？ |
| 空间与细节决定 | 哪张平面、节点、材料或效果图可以核对？ |
| 取舍与缺口 | 原文解释了什么取舍？还有哪些技术/使用问题未证明？ |
| 呈现办法 | 怎样让读者理解这条关系：图解、对照、全景、细节、说明？ |
| 可迁移条件 | 新项目何时可学这个方法？哪些原项目条件不适用？ |

每项注明“原稿明确 / 画面观察 / 研究解释 / Panda建议”。保留页码与必要短摘录即可；不抄大段原文或分发私人整套方案。方法卡引用多页关系，视觉卡引用具体构图，两者分开检索。

## 从案例到当前任务

迁移的是解决问题的方法，不是原稿的答案：

1. 对照当前用户的目的和已知条件，挑一条真正相关的方法。
2. 写清当前项目的证据、适用部分及不同之处。没有证据的内容只保留为建议。
3. 落成具体表达动作，例如“用同一平面的两个阅读层解释公共与私密”，而不是“学习大师的高级感”。
4. 选择能验证这个动作的真实材料和页面。若讲动线就要能阅读的平面/分析图，不能只给氛围照片。
5. 检查有没有把别人的人物、品牌、地域叙事、材料规格或优点移植成新项目事实。

对于非设计汇报，将同一方法简化为“读者问题 → 主张 → 证据 → 比较或取舍 → 所需决定”。不强迫用户先创作一个空间概念。

## 区分三种任务

- **读解原案例**：说明可见的概念与方案关系，承认未公开的理由。
- **表达用户已有方案**：以已定方案与用户理由为主，案例帮助组织证据和故事；缺失理由可以是解释候选。
- **协助方案共创**：从已知需求提出回应和备选取舍，标为新建议，不能把新建议写成已落地成果。

结构和视觉检查之外，要问：删掉所有形容词后，是否仍能说清问题、动作、证据与价值？若不能，继续读资料或改内容；不要用空泛文案占据图像阅读空间。
