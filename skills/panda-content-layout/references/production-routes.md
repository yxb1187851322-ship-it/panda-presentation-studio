# 制作路线：由素材、保真范围和编辑需求决定

先确定本轮用途、指定参考和允许改动，再选路线。下表是代理执行方法，不意味着本地工作台已自动实现。一个项目可以逐页采用不同路线，但必须逐页说明编辑范围，不能笼统写“全可编辑”。

| 路线 / `pages.mode` | 何时使用 | 实际制作与交付 |
| --- | --- | --- |
| 原生新稿 / `native-authoring` | 从已核实文字、数据与图片新建可编辑 PPT；没有指定固定模板 | 按表达任务与已选视觉系统制作原生文字、表格/图形及独立图片；不假称复刻模板，不必先生成整页图片再重建；渲染并检查编辑范围 |
| 原生模板 / `native-template` | 有适合的可编辑 PPT、设计文件或网页源码 | 先复制原件，读取对象与锁定区，在原槽位替换获准内容；渲染比较并检查对象可编辑性 |
| 整页保真 / `source-facsimile` | 指定原版只有 PDF、图片或压平 PPT；本轮需要保真阅读或基准 | 按原画幅等比使用整页，保留背景、边界和原署名；PPT 是整页图像，网页是原页查看器，不称可编辑复刻或新创作 |
| 参考驱动视觉稿 / `reference-visual` | 用户允许参考基础上的视觉制作，且需要高完成度样张或图片式 PPT | 先读内容与具体参考，用当前可用图像工具制作代表页，检查后组装图片式 PPT；适用于允许生成的视觉内容，不用于重画保真资产 |
| 可编辑重建 / `editable-reconstruction` | 只有视觉稿但确实需要修改文字、图像或简单形状 | 依照基准重建需编辑对象，复杂图像保留位图；逐对象、逐页对照，不承诺一键无损还原 |
| 展示网页 / `semantic-web` | 用户需要连续、响应式的作品网站 | 共享内容底稿，独立图片与 HTML 文字，按具体参考落实桌面/手机图窗及顺序；从真实源码渲染和操作检查 |
| 杂志图片 / `magazine-native` | 用户需要固定画幅的封面、海报或图片组 | 沿参考建立可编辑图文母版，再导出实际高清图片；图像占比按主体与页任务决定，不能套用固定分栏 |

## A. 原版继承优先级

用户已经要求沿用原版时，新的“开始制作”不自动解除原来的锁定。现有原生模板可用则优先复用；无原生对象则保真或重建。原生内容、位图文字、空占位框应实际核验，不能凭 `.pptx` 后缀判断母版可编辑。

复用版式与复用内容分别绑定。为 Panda 制作介绍时可学习第三方案例的图文关系，不能迁移案例的地点、面积、作者、客户或产品承诺。已给素材中的同图异名、缺标题和方案状态矛盾须保留为未知项。

## B. 参考驱动视觉稿的执行

此路线取用 [Codex PPT Skill](https://github.com/ningzimu/codex-ppt-skill/tree/85d4e629275e6c5793a33801d29b364383ea4c1e) 的内容大纲、具体参考、代表性样张、连续风格、逐页图像与讲稿备注流程。已读流程不等于完整原包执行；实际复用代码另保留其许可通知。

1. 写逐页内容：读者应理解什么、事实与来源、视觉角色、必须保留的文字和资产。页数与要点数根据内容，不继承固定目录。
2. 打开参考图并写具体关系：例如主图真实边界、题注与图片共用的轴线、正文容量、留白位置。每张输入标明“风格参考”或“项目原资产”；明确允许改变的区域。
3. 检查当前内置图像工具是否可调用。按其实际接口传入参考，先用 `view_image` 查看本地输入。由工具事实记录后端，不猜模型名称或无法配置的输出规格。不因方便批处理而先要求外部 API。
4. 生成一个能验证本轮问题的真实内容样张。使用本次文案和参考，不使用无关占位内容，不把封面美观当作内页通过。保存提示与结果；尺寸和中文质量以返回图片为准。
5. 对照来源和参考检查样张，记录具体问题。已有有效授权就继续该范围的工作；是否被用户认可单独记录。采用确认后的样张时，后续只继承视觉系统，不将内容页构图强制复制为同一种布局。
6. 逐页图片实际检查后按画幅组装 PPT，禁止拉伸。讲稿从已核实内容写入备注；组装只负责文件，不重新定义页面设计。检查导出是否缩图、压缩或损失小字清晰度。

上游逐阶段询问大纲、风格和后端的做法不是 Panda 的通用许可门槛。用户已经给出内容、参考和制作授权时，代理自行完成内部规划与样张，交付供审阅；绝不把授权制作记成认可结果。

### 必须保真的资产

CAD 几何与尺寸、工程图例、材料代码、Logo、图表数值和要求忠实的项目原图，使用原资产或经过核验的确定性派生件。它们不交给生图模型重画后当作原件。仅在提示词写“保持不变”不足以证明保真。

需要生成周边视觉时，保留明确空位，再用可用 PPT/HTML/SVG 制作工具放入原资产；这些放置不是重新绘制图片。记录原件、位置、比例、必要标签和实际产物，比较对应像素或视觉特征。如果没有可靠合成工具，采用可执行的原版/原生路线，不宣称已无损嵌入。此分离方法是 Panda 的制作要求，不能冒称上游已保证。

文字在生成图内时须核对每个事实、数字、字形和断行；密集材料表、尺寸和长段说明优先保留原生文字，或沿参考拆成相容内容页。不要靠无限重试让生图承担排字检查。

## C. 按需可编辑重建

作者的 [image-to-editable-ppt-skill](https://github.com/ningzimu/image-to-editable-ppt-skill) 是候选路线，当前仅研究过说明，未在 Panda 验证。使用前检查实际源码、依赖和可用工具，不声称已经安装或可一键无损转换。

本轮只需要图片式 PPT 时不强加重建。需要编辑时，先识别具体对象：正文与标签改为文本框，简单形状可重建，照片和复杂纹理仍为独立位图。保留视觉基准，检查字体替换、位置、遮挡、文字内容以及目标软件中的实际修改。只有被验证的对象能列为可编辑。

## D. 两套用户 Skill 怎样进入三端制作

用户提供的 `panda-magazine-layout` 与 `panda-editorial-website` 包含指导、图例和渲染/检查脚本；不能把它们称作现成 PPT 模板。存在原包时按[资料路由](library-routing.md)定位并读本次需要的分支，实际打开对应图例；没有原包时使用本 Skill 的已整理方法，不声称运行了原包。

| 可复用步骤 | 杂志图片 | 网页 |
| --- | --- | --- |
| 原图分析 | 主体、空间轴线、有效像素、裁切安全区 | 同左，另登记图片到章节的覆盖 |
| 参考分析 | 第一焦点、真实图幅、文字重量、空白形状、同组节奏 | 同左，另查看真实滚动；静态截图不能证明动效时序 |
| 制作 | 先主图窗口和主体保护区，再文字；可编辑源与高清输出分开 | 真实 HTML 文字和独立图像；手机单独组织比例、顺序和断行 |
| 核对 | 实际像素、母版与 PNG 一致、100% 细节、原图细节上限 | 桌面/手机、滚动中间帧、按钮、减少动态、离线资源与横向溢出 |

图片正式尺寸按任务或所用包的生产要求；普通预览截图不称高清成品。网页先交完整目录或适用的自包含文件，公开链接须实际部署；本地地址不称外部已上线。沿用固定原页时可以做查看器，但不能把它称作响应式图文网站。

用户明确要求“手机能读的网页”时，允许为阅读所必需的响应式顺序、文字断行和图窗调整，同时保留参考的视觉关系及 Logo、图纸、品牌锁定，不据此重新创作一套风格。若同时要求两端像素一致，应说明这与手机正文可读性的具体冲突，完成兼容部分；不能默认以整页缩小查看器替代已要求的手机图文阅读。

## E. 执行能力与集成状态

| 能力 | 当前如何使用 | 不能据此宣称 |
| --- | --- | --- |
| 内容与参考分析 | 代理实际读取资料、看图，保存证据 | 本地规则规划器已调用多模态模型 |
| 图像生成 | 当前宿主内置工具确实可用时，由代理调用 | Panda 正式客户端已接入该后端，或模型型号固定 |
| PPT/HTML/图片制作 | 核验当前库和渲染工具后执行；逐项记录实际运行 | 写入成功就等于渲染、宿主编辑、审美已通过 |
| 制作记录检查与打包 | 配套仓库提供脚本时，检查字段、声明和文件，并封装已有结果 | 自动理解内容、自动审美或自动生成整本 PPT |
| CAD、扫描 OCR、母版继承 | 以任务实际解析与渲染证据判断；未知保持未知 | 软件存在、上传成功、读到零碎文字就表示完整解析 |

只有实际调用、产生文件且核验的步骤标为已执行；未接入能力保留为未验证或候选。可交草稿与完成制作分别判断，避免为了流程字段齐全虚构证据。
