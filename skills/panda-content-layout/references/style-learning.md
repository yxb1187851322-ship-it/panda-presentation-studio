# 从好作品积累 Panda 的视觉方法

先分清页面要完成的表达任务，再学习好作品怎样处理图文关系。风格可以有多个分支，不把一套字体、米色背景或固定图片占比称为全部 Panda 风格。

## 每次学习留下什么

选实际看过的代表页，记录：第一眼看见什么、为什么；原图完整范围和画幅；图与题注共用的轴线；标题、正文、标签的重量差；留白在哪里帮助阅读；前后页如何改变节奏。另写清适用的图片比例、内容密度、用途和不适用条件。

把观察转为可执行关系，例如“原图完整等比显示、说明贴合图边且不抢主图”“两张相关细节保持相同高度，图注位于各自图片下”。只有需要精确复用时，才从原生模板或已测量画面登记尺寸、字体和坐标。不能捏造测量值，也不从风格名称推导这些值。

设计推演方法与视觉关系各有来源：一个案例可能提供很好的逻辑，但画幅并不适合当前图；一个模板可能好看，却放不下本轮论证。允许组合经过验证的关系，避免拼凑互相冲突的网格和文字层级。

## 用真实内容试排，再保存反馈

候选 → 实际内容试排 → 看图与用户反馈 → 在已验证范围内复用。用户否定则保留具体问题并退出推荐；新版另立版本。尚无真实样页的规则停留在候选。

认可必须指向哪一版、哪些实际页面、认可什么。封面被接受，不说明图纸、材料、长文和手机页均已通过。改变布局、字体或关键比例后，用新样页检查，不能继承旧版认可。用户本轮明确要求再试曾否定的方向，可以局部试验，不将其恢复成通用成功模板。

没有必要给每张页面虚构一个“审美分”。并排查看参考、输入原图与输出，分别记录可见的问题：图像是否过小，背景是否割裂，层级是否失衡，阅读顺序是否清楚，重要内容是否被裁掉。这些是检查线索，最终取舍由本项目目标与反馈决定。

## 与代码的关系

完整开发仓库的 style-profile 模块保存候选、试排、认可、否定及版本关系，并检查图纸/Logo的完整放置和使用条件。它检查结构化记录，不能替代看图，也不能证明调用方提供的反馈是真实用户反馈。单独使用本 Skill 时，可以在工作底稿中保存同样的关系，无需安装开发模块。

研究原件留作方法证据；可复用的模板、字体和素材按实际授权登记。客户的私人文件不随通用风格包分享。只有实际运行过的外部 Skill，才写入本轮执行记录。
