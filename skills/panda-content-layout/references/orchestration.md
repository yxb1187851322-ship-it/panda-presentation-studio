# 复合智能体的协作边界

用于Panda产品开发或多模块工作流，不把本规则包本身当成已部署应用。使用者面对上传、对话、预览与修改；后台按需运行理解、品牌、内容、设计、图像处理、制作、复核模块，不要求使用者选Skill。

区分产品外壳、编排器、模型、专业规则、执行工具和资料库。模型负责推理与理解，解析器负责实际文件结构，制作工具负责文件，真实渲染用于复核。一个模型可承接多种角色；模块分工不要求每个模块部署一个独立代理。

## 模块交接

输入保存project_id、任务、asset_ids、content_ids、brand_constraints、输出类型与允许修改范围。input_snapshot包含素材、内容、品牌、版面、授权版本及本任务实际依赖。结果返回证据、产物位置、版本、未知项、检查状态和具体错误。实例见[交接示例](../examples/design-handoff.example.json)。

共享底稿由编排器统一提交；并行模块返回提案，不直接互相覆盖。异步结果提交前比较实际依赖版本，包括换Logo、收紧模板锁定或撤回编辑授权。旧版本结果保留为旧稿，不覆盖用户刚更新的资料。

图片生成和导出保存任务ID及输入指纹。重试前检查已完成任务；记录预算、超时和可配置返修上限。按问题来源定向返修，不无限循环或每次推倒整套。遇到服务能力不足完成独立可做部分并说明具体限制。

超时但可能受理的任务标为结果待核实，优先查询原任务或使用已支持的幂等键，不能核实就不直接重发付费请求。明确失败、结果未知、已取消、被新版本取代分别记录。

服务执行状态与结果采用状态分开：上游可能仍未知，但本项目可明确禁止采用。用户撤回编辑要求时停止相关排队/重试，服务支持则请求取消并核验；迟到结果只归档为未采用，不进入新版。未确认上游取消成功时不标服务已取消。

## 按能力选择模型

理解角色需实际图像输入及中文/空间材料处理能力；设计角色需遵循来源和品牌约束；图片角色需参考保真与局部编辑；复核角色需实际看渲染。候选称呼、应用内模型显示名、厂商API型号分开，按实际目录和测试记录绑定model_id。

只检查本次任务所需能力。模型输出结构有效仍要核对事实与引用。服务端保管凭据，客户端不暴露密钥；本项目允许的资料才送给选定服务。产品网站与客户输出网页是不同交付对象。
