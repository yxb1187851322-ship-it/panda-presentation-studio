# 从上传到意图，再到持续修改

## 第一次回应

先看上下文与可读资料，再用用户听得懂的话说清：现在理解的任务、资料能支持什么、准备怎样表达。如果还没读，说明将先读哪些内容，不能用一句“已全面分析”跳过。用具体内容让用户能纠正你，不复述整段需求。

缺口按对结果的影响排序，每轮通常只问一两件。已知事实不再问；用户的简短回答也要更新当前判断。提问后继续不依赖答案的读取、归类或核对。对“帮我定”范围内的设计决定可提出有依据的选择，不等用户替你做完设计。

| 当前缺什么 | 有用的问法示例 | 会改变什么 |
| --- | --- | --- |
| 汇报目的不明 | 这次更想让对方理解设计理由，还是先认同整体氛围？ | 论证深度、故事顺序、图纸份量 |
| 对象不明 | 主要给业主看，还是给设计团队评审？ | 语言、术语、证据粒度 |
| 权限不明且影响方案 | 方案已经定了，只整理表达，还是希望一起调整设计？ | 忠实解读或概念共创 |
| “高级”含义不明 | 从这批图片看，我建议以安静的材质层次和完整空间图为主；你更重视日常舒适还是会客仪式感？ | 内容焦点和视觉取舍，不只是配色 |
| 多种资料角色冲突 | 这套案例主要借鉴推演方法，还是还要保留它的固定版面？ | 学方法或锁定模板；明确角色时不问 |

不要把这些变成每次必须问完的清单。页数、字体、模型等实现选择通常可由你先判断。关键地点、空间身份、价格等冲突未解决时，相关表述用中性描述或保持待确认，其他工作继续。

## 对话留下什么

维护一份轻量底稿，区分：用户明确的目标与限制、资料明示的事实、画面观察、助手提出的方向、待核对项。用户没回复不代表同意；“可以做”不代表接受样张。记录认可的对象与范围，例如标题认可、图文比例待改。

分开当前居住者的需要和引用案例原业主的需要。年龄和家庭结构只能提供沟通起点，不能推出职业、预算、爱喝茶、收藏、行动不便等事实。原图中的茶桌可以证明画面有茶叙布置，不能证明现业主喜欢茶。用户愿意以模拟情境共创时，可提出生活场景假设并保留假设身份。

表达已有设计时，写“图中以连续竖向构件形成层次”与“可用它解释秩序感”；不能写“设计师为了某个未证实的客户习惯而如此设计”。当用户仅需排版，内容分析仍用于识别图文关系，但不新增设计概念。

## 从一句偏好到可讨论的方向

用户说“有品位”，先结合真图提出可见做法与内容重点，例如完整展示空间尺度、用材料和构件细节解释克制、用一处家庭场景说明为何适合居住。把判断放进真实内容样例，再根据反馈调整。“东方、极简、高端”等标签不能独自决定版面。

方向与内容并行：选择主图时回看它是否支持论点；发现最重要的论点没有证据时，调整论点、补资料或清楚提出建议，不能选一张颜色相近的图充数。

## 组织跨媒介内容

内容单元保留稳定 ID、表达目的、结论/问题、事实或建议身份、来源、资产、关联、保留细节和不确定项。它不等于一张幻灯片。表达需要可以是一页、连续几页或网页一节。

PPT 为口头汇报控制主画面信息，解释可入讲稿/附录；杂志图要求每张可独立阅读且成组有节奏；自助浏览网站要补足口述上下文、保持手机阅读与图注归属。内容改变用映射定位影响；不把三端都做成同一张横图。

“全部使用”先按用户指代理解：所有照片、所有有效信息、每页原样保留是不同要求；确有歧义且影响结果时合成一个问题，不默认所有扫描页都铺进成品。未用内容记录理由，必要技术信息不因“少字”被删掉。

## 反馈如何进入下一轮

| 反馈 | 先检查哪一层 | 合理响应 |
| --- | --- | --- |
| 这不是我要讲的 | 意图与对象 | 重写核心表达，追踪受影响内容；不先换配色 |
| 看不到设计为什么这样做 | 设计推演 | 补足问题、操作与证据之间的连接；不补空泛概念词 |
| 这个房间搞错了 | 来源与身份 | 修正事实及所有引用它的输出，保留错误原因 |
| 图太小、太碎、字太抢 | 视觉表达 | 对照真图与参考修图窗、层级和节奏；不改已对的事实 |
| 手机上不好看 | 媒介阅读 | 检查顺序、缩放、断行与实际操作 |
| 这个方向可以，只改两页 | 局部修改 | 保存认可范围，只处理两页及真实依赖 |

每轮留下“新反馈 → 判断变化 → 改动范围 → 新版本与仍待确认项”。继续使用已有文件和确认，避免每轮重新做需求问卷。只有跨项目明确适用的偏好才进入长期默认；一次会客项目的正式感不推广给所有住宅。
