# Panda 汇报与内容编排

**v0.12 增量：** 工作台已采用既有 Panda Logo 与黑白配色，少量银色点缀；新增独立精排册子模块，支持由代理编排并复核后输出。它尚未接到聊天自动路由，本轮真实模型尝试的失败与代理交付分别记录，见 [黑白界面与精排册子](docs/黑白界面与精排册子_v0.12.md)。

**对话创作入口（v0.11 起）：** 打开本地工作台，上传图片或文件，在同一个对话框里说出想做什么。Panda 按需理解资料、追问、编排和制作，结果直接出现在对话里。无需先填写项目表单，也无需分别操作分析、规划和导出按钮。使用示例见[对话创作](docs/对话创作_v0.11.md)。

例如，先上传资料并说“这是住宅方案，请先帮我理清汇报思路”；讨论后说“按这个方向制作 PPT”；看到结果后说“第 3 页图片放大，文字缩短”。生成后可直接下载 PPT、打开网页、逐页查看或保存图片。右上角只保留新对话和历史对话入口，旧项目仍可继续使用。

模型和 [Panda Skill](skills/panda-content-layout/SKILL.md) 负责理解与编排，本地制作器生成文件。当前默认 `gem-3.8-flash` 负责分析、对话与改稿，`tt-6.1-sol` 负责规划；名称为接入平台 ID，未独立核验官方上游身份。v0.11 已通过 187 项自动化测试，并在浏览器以模拟模型完成真实上传、制作、改稿和导出；新对话入口的付费模型意图识别尚未实测。详见[本轮验证范围](docs/对话创作_v0.11.md#验证范围)。

**历史 v0.10 的实测证据：** 2026-10-12 使用 15 张图片预览与 6 份文档提取文本，完成分析、对话、规划、局部改稿，实际导出 10 页 PPTX、离线 HTML 与 10 张 PNG。真实调用 4 次成功、1 次超时失败后退款，实扣 0.4277 算力；当时 171 项自动化测试通过。这些属于 v0.10 记录，不是 v0.11 新对话链路的实测结果，也不是后续费用或耗时承诺。详见[模型与技能运行](docs/模型与技能运行_v0.10.md)。

v0.9 的[专业流程](docs/意图与设计推演_v0.9.md)与[内容状态接口](docs/技能封装与接入_v0.9.md)继续保留：案例方法、视觉参考、项目资产与固定模板分开处理，已有内容证据与风格版本模块。历史 workflow 底稿与 `project.ai` 数据保持分开，新界面不再展示复杂的工作流面板。Panda 正式客户端仍未接入。v0.8 制作路线与样稿封装命令见[历史说明](docs/制作流程_v0.8.md)。

**运行方式：** 安装本地依赖并配置服务端 API Key 后，可从浏览器工作台触发模型任务，不必每次借助 Codex 执行。模型提出结构化内容与页面计划，本地制作器写出文件；当前只支持六类有限版式，不能自动实现任意设计或完整继承固定母版。Skill 也可由具备相应工具的助手宿主加载。分工及验收见[运行边界](docs/架构与客户端接入.md#当前怎样运行模型与-skill-怎样接入)。

Panda 现有本地客户端中的内容编排能力：理解用户上传的图片、文档、图纸与品牌资料，设计内容结构，再按用途制作可编辑 PPT、项目展示网页或杂志图片。未来网页客户端复用项目与任务协议。

**历史 v0.7 的规则制作链继续可用：** 支持上传、文本提取、规则编排、逐页修改和真实 PPTX / 离线网页 / 页面 PNG 导出。PPT 文字可编辑，原图作为独立图片对象；图片内部的家具、线条和文字不会变成原生对象。既有导出测试不能代替本轮模型新稿的实际文件与目标软件验收。CAD、扫描文字与固定母版完整继承仍待实现。

首轮样稿已被用户否定图文比例与版面关系。本地正在按原稿重新校准图片比例、题注、纸色和留白；设计卡目前只返回研究候选，尚未自动转成渲染约束。技术可导出不能作为设计已通过的依据，详见[反馈与验证记录](docs/验证记录.md)。

## 运行

需要 Node.js 22 或以上。核心规则无第三方运行依赖；制作工作台需要 `@oai/artifact-tool`、`sharp` 与带 `pypdf` 的 Python，使用已有运行时或自己的安装环境。API Key 由服务端从 `.env` 读取，可在忽略的 `local/ai-config.json` 指定配置；不要把真实凭据写进 Skill、浏览器、日志或公开仓库。配置示例与输入限制见[模型运行说明](docs/模型与技能运行_v0.10.md)。

发送消息后，Panda 按需将相关说明、对话上下文、压缩图片预览和可提取文字交给配置的模型服务，并产生 API 调用费用；一次制作可能包含理解和规划等多次调用。原件与项目记录保存在本机，不自动上传 GitHub。已完成的页面仅重新导出文件时不需要重复调用模型。详细数据和调用记录保留在本机。

```text
npm test
node scripts/start-studio.mjs
node --test test/core.test.mjs
node scripts/verify-resources.mjs
node scripts/local-library.mjs status
```

工作台默认打开 `http://127.0.0.1:4317`。配置方法见[本地工作台](docs/本地工作台.md)。`prototype/index.html` 保留为旧概念原型，仍没有上传和导出功能；实际制作使用新工作台。

本机资料关联方式见 [本地资源使用](docs/本地资源使用.md)。`local/library.local.json` 仅用于开发机定位原稿，不提交 Git；其他电脑可用自己的资源根目录创建绑定。仓库无需这些私人文件也能运行核心测试与界面原型。

## 文件职责

| 位置 | 维护内容 |
|---|---|
| `skills/` | 专业规则与按需参考，当前规则主版本 |
| `resources/design-library/` | 来源页码、视觉观察、设计推导、适用与反例、阅读范围 |
| `resources/sources/` | 外部工具来源与本地清单格式；实际原件清单只保存在忽略的 local 目录 |
| `src/core/` | 内容证据与改稿状态、风格候选与反馈、任务采用与交付检查规则 |
| `docs/` | 产品事实、流程、接口、阶段验收 |
| `prototype/` | 可点击的界面示意，不连接生产服务 |
| `studio/` | 实际本地工作台界面 |
| `src/intake/`、`src/planner/` | 原件保存、受限文本读取与可解释规则编排 |
| `src/ai/` | 服务端模型网关、Skill 装载、证据分析、页面计划和对话动作校验 |
| `src/renderers/`、`src/server/` | 真实导出与本机服务，不连接生产客户端 |
| `examples/` | 明确标注的虚构数据 |
| `scripts/` | 资源校验与本机原稿定位 |

对外复用的是经过整理的设计方法。第三方案例不是客户新项目的素材，也不能把研究卡命中当成已经完成设计。Panda 自身界面遵循其品牌，客户成品遵循客户的 Logo 和固定版面。

> 设计反馈：历史多轮样稿未获认可，继续保留失败记录。用户进一步明确，参考案例主要用于学习设计从问题到方案的推演，而非一概照搬版面；明确指定固定模板时仍须继承。现有规则排版器不能冒充语义理解或严格模板继承；整页图片 PPT 不称可编辑母版。
