# 实施顺序与验收

## 当前已经具备

开发底稿、逐页设计研究、专业规则、纯函数核心及界面原型。核心不发模型请求；原型不生成文件。测试通过的范围以仓库验证记录为准，未运行的能力保持未验证。

## 下一步先做同材料试排

从用户选定的一个真实项目取图片、文档、一个平面和可用品牌资料，先做能覆盖主要设计问题的少量页面。建议覆盖开场、主图、方案对比、平面、材料；具体数量随内容确定，不变成固定五页模板。

做两条 PPT 制作路线的对比，记录实际文件、逐页渲染、哪些对象可编辑及不能保真的情况。选一段内容延伸到手机网页和杂志图片，检验“共享事实、分别设计”是否成立。

## 分阶段推进

| 阶段 | 产物 | 进入下一阶段的证据 |
|---|---|---|
| A 资料与方法 | 本轮仓库、案例索引、阅读范围、规则、原型 | 目录可读、来源可定位、实际与规划分清 |
| B 真实设计试排 | 原生 PPTX、渲染图、跨媒介样例、用户改稿 | 内容可信、中文和图纸可读、品牌继承、局部修改可追溯 |
| C 客户端最小接入 | 正式客户端一个入口、文件列表、任务与预览、导出 | 真正从上传走到交付，失败可恢复、旧任务不覆盖新版 |
| D 多模型与三端扩展 | 可替换能力适配、图像处理、网页/图片正式产物 | 使用范围与成本可见，三端内容版本一致，编辑保真经过测试 |
| E 反馈与产品化 | 使用记录、失败样本、候选规则与版本发布 | 用户任务成功率和修订原因可统计，质量改进有实际证据 |

阶段 C 以现有 Panda 客户端为宿主；未来网页客户端采用相同合同。不在阶段 A 重做账户、官网、积分和整个平台。

## 必须覆盖的真实验收场景

1. 只有图片：不编项目面积/地点，仍能形成合理图文结构。
2. 多种资料：每份原件有用途与可读范围；未用资料有原因，不静默遗漏。
3. 模板与 Logo：固定区域不漂移，中文长标题不溢出。
4. 图纸：保持等比与必要范围，标注可读；无原生 CAD 解析就不报成功。
5. 材料编号：页内编号、图例和列表一致；材料意向不变成采购规格。
6. 任务超时、取消与换 Logo：未知任务不重复提交，迟到结果不盖新版。
7. 用户手改回传：保留外部修订，只定位真实冲突。
8. 多端改事实：列出受影响内容，按授权更新，未更新产物明确标旧版本。
9. 网页手机和减少动态：顺序、图注、交互与完整滚动内容可用。
10. 真实交付：目标软件能打开；原生对象及图片对象的编辑范围清楚。

## 怎么判断体验有改善

记录首个可审阅稿耗时、需要补问次数、每页实质性改稿原因、事实/品牌/技术错误、局部修改是否意外影响其他页。审美反馈记录具体页面与取舍，不只收一个满意分。未形成真实样本前不设伪精确的成功率或行业基准。

## 本轮未完成的产品能力

正式客户端接入、实际模型路由、解析与渲染服务、可编辑 PPT 输出、上传与下载服务、联网发布、商业运行监控。下一阶段需要正式客户端接口证据和真实材料试排；这些缺项不由静态测试消除。
