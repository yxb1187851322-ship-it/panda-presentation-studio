# 模型与技能运行 v0.10

用户只需要一个入口：上传资料，说明想表达什么，查看结果并继续修改。后台按阶段读取专业方法、调用模型与制作工具。当前优先完成本地可用链路，不以正式 Panda 客户端接口为前提。

本轮将模型接口与工作台连接起来。**代码接入、真实 API 调用、内容正确、PPT 文件可用和视觉获得认可，是五项不同的证据。** 下文是实现约定与验收范围；最终运行结果须结合本轮实际记录，不将模型 ID 或可用按钮当作成功证明。

## 三部分一起工作

| 部分 | 做什么 | 如何证明实际工作 |
| --- | --- | --- |
| 模型网关 | 将任务发送至已配置的模型，处理文字与实际图像输入 | 记录实际供应商 ID、成功或失败、耗时和返回用量；不回显 Key |
| 专业 Skill 与编排 | 理解受众和意图，学习案例推演，组织有依据的内容，再制定页面计划 | 记录本轮加载的方法文件及哈希；底稿中能追溯论点、来源与图片用途 |
| 本地制作工具 | 用页面计划与原资产写出 PPTX、HTML 和 PNG | 实际文件及本轮预览，区分可编辑文字、独立图片与图片内部内容 |

只加载 Skill 可以让具备工具的助手遵循专业方法；独立网页还需要后两者配合。一个通过验证的多模态模型配合受约束的制作工具，足以开始最小链路，无需先复制完整编码代理。

## 按什么顺序编排

1. **读取资料。** 保存原件，提取当前支持的文字，向视觉模型提供实际图片或有效预览。文件数量、读取页数及缺失范围可见。
2. **弄清要说明什么。** 将用户的目的、受众和资料事实整理为内容底稿。仅追问影响判断的问题，不从年龄、性别编造职业与生活习惯。
3. **建立有依据的表达。** 参考案例提供“问题怎样推到设计回应”的方法。回到本项目确定论点、图像证据、需要解释的取舍与汇报顺序。
4. **制定页面计划。** 每页明确读者应该理解什么、哪张图证明、文字保留多少、哪些品牌或图纸约束不能改变。
5. **制作与看稿。** 渲染器完成真实导出。把内容与实际页面一起检查，图文关系、画幅和可读性必须看图判断。
6. **按反馈局部修改。** 更新相关事实、论点或页面，保留不受影响的内容；旧预览明确过期，修改后重新制作。

用户不需要自行依次触发六个 Skill。编排器按阶段读取 [主 Skill](../skills/panda-content-layout/SKILL.md) 和相应参考；需要专门模板、图片处理等能力时再追加适用分支。研究过外部 Skill 不等于已经运行它的实现。

## 模型如何选择

先用真图和中文资料验证多模态分析，再比较叙事与约束遵循能力。将较复杂的逻辑或改稿分配给需要的模型，纯文字整理可使用更轻量的模型。不要同时调用多个模型来制造“已复核”的印象。

本次供应商目录候选 ID 为 `gem-3.8-flash`、`tt-6.1-sol`、`deepseek-v4.1-flash`。当前配置把 `gem-3.8-flash` 用于分析与局部改稿，把 `tt-6.1-sol` 用于页面规划；`deepseek-v4.1-flash` 作为尚未实测的备选。局部改稿最初使用 `tt-6.1-sol`，真实请求发生供应商连接超时，核实最终失败及退款后才手动切换模型，系统未自动付费重试。这些是供应商接口 ID，名称不证明对应某个官方型号，也不证明都支持图像。当前分工仍需更多实际质量与稳定性检验，不是最佳模型结论。

网关实现 Gemini、OpenAI 兼容与 Anthropic 协议，依服务返回的 `api_format` 选择；协议兼容不等于所有模型能力一致。密钥从服务端配置读取，不写进 Skill、浏览器或公开仓库。用户已授权在选定服务处理的本轮资料才可送入模型。

## 本地入口与配置

使用配套工作台，不需要在每次制作时手动执行 Skill 文件。服务启动与制作依赖见[本地工作台](本地工作台.md)。服务端从 `.env` 读取 `API_KEY`；可通过 `PANDA_ENV_FILE` 指定位置，也可在忽略的 `local/ai-config.json` 中设置 `envFile`。共享代码只保留配置方式，不提交真实密钥或私人绝对路径。

`local/ai-config.json` 可配置：

```json
{
  "models": {
    "analysis": "gem-3.8-flash",
    "planning": "tt-6.1-sol",
    "revision": "gem-3.8-flash"
  },
  "maxOutputTokens": 8000,
  "maxEstimatedCost": 2
}
```

每次付费调用前核对该 Key 的可用模型渠道、价格与余额。`maxEstimatedCost` 为请求前估算的拦截阈值，单位“算力”；图像计费、推理用量等可能与估算不同，**不是实际扣费的保证上限**。失败不自动再次发起付费请求。

开发接入使用以下动作；用户界面应转为直接描述任务的按钮和对话：

| 入口 | 用途 |
| --- | --- |
| `GET /api/ai/status` | 查看配置和已验证调用状态；不返回凭据 |
| 项目 AI 入口的 `analyze` | 实际分析本轮图片和可提取文字 |
| `chat` | 按补充信息更新分析与关键问题 |
| `plan` | 以已有分析形成制作器可执行的页面计划 |
| `revise` | 根据指定页与反馈修改一页，保留其他页 |

AI 项目入口为 `POST /api/projects/:id/ai`，提交项目当前版本及相应动作，使用工作台既有本地认证。页面计划生成之后仍需执行导出；模型回复本身不是 PPT 文件。

本轮模型输入最多 24 张压缩预览图，最长边 1440 像素；单份文档发送最多 18,000 字符，全部文档合计最多 60,000 字符。超出或无可读内容的资料列为未发送，不能默认为分析完成。压缩图纸用于可见内容观察，不能据此核验尺寸或细小标注。输入规模和模型费用约束都通过后才提交请求。

## 本轮验收与后续边界

2026-10-12，独立住宅试排已跑通**真实资料分析 → 对话修正 → 10 页页面规划 → 指定页改稿 → PPTX、HTML 与 PNG 导出**。局部改稿首次调用发生供应商超时，确认失败及退款后手动切换模型成功；其余 9 页保持不变。4 次成功调用与 1 次最终失败均保留记录，平台报告实扣合计 0.4277 算力。具体证据见[验证记录](验证记录.md#v010-模型链路实测)。

本轮已检查实际文件结构、内容、页面边界与 10 页渲染；PowerPoint/WPS 中真实打开及手动编辑尚未测试。逐页查看发现封面孤字断行后，已在界面手动修正并重新导出、查看，说明技术检查不能替代真实看稿；内容顺序与宋式设计推演也有提升空间。模型接通和文件可导出成立，审美获得认可仍未成立。

| 验收 | 通过证据 |
| --- | --- |
| 模型可用 | 真实请求返回可用内容；Key 存在或 HTTP 200 不是完整任务通过 |
| 分析可信 | 真图和文本实际进入请求；空间身份、出处、冲突和未知项可以核对 |
| 内容说得清 | 每页论点与证据相连，用户能识别它在回应什么问题 |
| 文件可用 | 本轮 PPTX/HTML/PNG 实际生成；目标软件打开与编辑的检查单独记录 |
| 改稿可控 | 指定页变化正确，未受影响页保留，过期产物不冒充新版 |
| 视觉可接受 | 实际内页与明确参考比较，并记录用户对具体版本的反馈 |

模型自评、JSON 校验和自动化测试均不能证明“高级”或“好看”。已有用户否定的版面继续作为失败样本，不因接入模型重新成为默认方案。

当前解析与渲染能力仍有范围：原生 CAD、完整扫描 OCR、固定母版保真继承、独立竖版杂志构图、自动视觉审稿及正式 Panda 客户端接入，需要各自的实现与验收。当前工作不因这些后续能力尚未完成而停止，但也不将它们写成已具备。
