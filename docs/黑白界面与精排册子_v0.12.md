# v0.12：黑白界面与精排册子

更新：2026-10-13。这个版本继续保留单一对话入口，同时增加可复用的精排渲染器。本轮真实自动模型尝试没有完成制作；代理审读与精排交付属于另一条已明确区分的执行路线。

## 界面与品牌

工作台以黑白灰为主，仅在小面积控件或线条中使用银色质感。上传、输入、发送仍是主要操作，历史和新对话保持轻量入口。

`studio/assets/panda-logo-light.png` 来自用户既有 Panda 品牌资产，用于工作台识别。它替换此前不符合用户要求的自制图形，不代表重新设计了 Panda Logo。工作台品牌与客户作品品牌分开；客户导出的册子不因为在 Panda 制作就自动加上 Panda 标识。

页面的黑白配色不等于给上传效果图去色或改造室内设计。原图色彩、比例与图纸边界需按任务保留；银色点缀不能压过项目图片。

## 本轮真实模型尝试的结果

本轮通过既有对话 API 上传了全部项目输入并发起真实模型分析，随后只进行一次格式修复尝试。两次响应均未通过本地结果校验，自动流程没有进入页面规划与导出。

因此，本轮最终册子由代理读取素材、复核事实、组织设计解释、编排页面并检查结果，不能写成「全自动一次生成成功」。模型返回结构正确、内容有证据、页面好看、文件可编辑是不同检查，任何一项都不能替代其他项。

针对这次失败，代码已增加校验前的脱敏原文留存，并仅兼容顶层唯一 `contract` 包装且内部字段完整的响应。解包后继续执行原有校验；不猜测其他嵌套，也不重新发起付费请求。修复通过自动化测试，但本轮没有追加真实模型重跑，所以不能把之前的失败改成自动生产成功。还需针对无依据面积口径、朝向和材料功能扩写增加内容校核。

## 精排制作器的使用范围

新增 `src/renderers/editorial.mjs`，接受明确的页面场景数据：画布、背景、文字、图片位置与来源。它检查基本坐标、颜色、图片路径和裁切范围，输出 PPTX 候选文件、逐页 PNG、网页查看器和 PDF。

这个制作器是可复用的独立模块，当前没有自动接入聊天模型的页面规划路由。它不代表现有模型已经能够自行产生任何杂志版面，也不会自动判断一个页面是否高级。代理或调用者仍需先完成资料阅读、内容确认、场景编排和实际页面检查。

具体接口见 [editorial.mjs](../src/renderers/editorial.mjs)，现有常规导出器继续保留。可使用单独的输出目录，避免覆盖旧稿；场景中的图片必须来自指定素材根目录内，不能借路径跳出读取其他文件。

代理或程序可通过 ESM 导入调用，不需要在界面新增复杂操作：

```js
import fs from 'node:fs/promises';
import { renderEditorialBook } from './src/renderers/editorial.mjs';

const scene = JSON.parse(await fs.readFile('./work/book.scene.json', 'utf8'));
const { candidate } = await renderEditorialBook({
  scene,
  assetRoot: './work/input',
  outputDir: './work/book-v1', // 必须是新的空目录
  pngShortEdge: 2160,
});
```

运行前通过 `PANDA_NODE_MODULES` 提供已有制作依赖，通过 `PANDA_PYTHON` 提供 Python。场景中的图片路径相对 `assetRoot`。输出的 `candidate` 仍是待验收 PPTX；本轮由 Codex 调用宿主的 `finalizePresentation` 做包结构、布局与字体检查，再生成正式 `booklet.pptx`。宿主检查器与项目专属场景不随本仓库分发，其他调用方应接入自己的等效验收，不能直接把候选文件标成已通过。网页中的 PPT 下载入口以正式文件完成为前提。

## 文件的编辑范围

- **PPTX：**新增标题和说明为原生文字对象；每张来源图是独立图片对象。图片内部的家具、平面线条与原有文字仍是像素，不成为可编辑 CAD 或原生图形。
- **PNG 与网页预览：**按已渲染页面展示，网页提供翻页、文字阅读以及成品下载入口。预览图不是任意宽度重新排版的网页正文。
- **PDF：**优先尝试制作引擎的 PDF 输出；遇到已识别的标准字体依赖问题时，可调用 `src/renderers/pdf-from-previews.py`，以逐页 PNG 生成保留画面的 PDF。该降级文件为栅格页面，不能描述为矢量文字 PDF。

预览式 PDF 降级需要 Python 与 `reportlab`，通过 `PANDA_PYTHON` 指定 Python。原有 Node 运行环境与制作依赖继续适用。技术检查通过后仍需查看实际页面；PowerPoint/WPS 的最终编辑表现及用户审美认可应单独记录。

## 打包与后续复用

源码快照包含通用代码、测试、文档、Skill 与界面 Logo。私人项目资料、项目数据、模型调用原文、真实凭据、本机路径清单和 Git 历史不进入代码包。Logo 按二进制文件打包，不以 UTF-8 文本解码。

Skill 包仍由 [panda-content-layout](../skills/panda-content-layout/SKILL.md) 提供内容与设计规则。v0.12 包名表示本轮交付快照，不能据此认定每个内部模块都升级了版本或所有宿主已完成安装。

本轮完整自动化测试为 **195 项通过、0 失败、0 跳过**，资源校验通过31张卡。工作台页面、样式与 Logo 的 HTTP 请求可用，Logo 保留原文件字节。实际浏览器已检查1280×720桌面与390×844手机画面；手机文档宽度390、输入框右边界376，无水平溢出。

册子逐页预览与重新打开的PDF另行检查；其网页翻页交互未在本轮浏览器验收，不与工作台界面检查混为一项。

测试结果以本轮最终日志与打包回执为依据。它验证可执行行为及已覆盖的异常情况，不证明陌生输入都能自动产出合格设计，也不把历史未通过的审美反馈改写为通过。
