# Panda 产品定位与边界

更新：2026-10-12。公开文档只保留本模块需要的产品背景；内部原始证据及文件定位保存在本机。

## 当前基线

用户确认 Panda 当前是本地安装客户端，已有官网，后续提供网页客户端。本仓库开发其中的汇报与内容编排能力，面向室内设计师与设计团队。

Panda 的背景资料强调设计师、智能体、知识库、多模型和画布之间的协作，重视项目判断持续传递、成果可修改与复用。它们是产品结构依据，不表示本仓库已经实现全部能力。

设计流程先理解项目、使用者与问题，再形成概念、风格、参考和出图策略。空间图片先看结构、比例、材料、光源和镜头；汇报编排增加表达对象、叙事顺序和媒介适配。

## 不同交付对象

| 对象 | 本次关系 |
|---|---|
| Panda 现有本地客户端 | 首个接入宿主，提供上传、对话、项目与预览入口 |
| Panda 现有官网 | 既有产品入口，本仓库不重建 |
| 未来 Panda 网页客户端 | 后续消费同一项目与任务协议 |
| 客户导出的项目展示网页 | 一种作品交付，使用项目品牌，可本地交付或按授权发布 |

正式客户端技术栈、扩展接口及现行模型清单尚未在本仓库中核验。独立工具、示例或同名候选程序不能代替正式产品接口证据。

## 品牌与知识的边界

Panda 自身界面可采用克制的黑白灰、清晰层级与留白；客户成品遵循客户品牌及当前授权。上传固定版面时先识别锁定范围，不能用排版升级覆盖既定品牌要求。

内部框架缺少正式定义的部分不写成产品合同，不猜测未确认的功能、接口或规则。公开设计库使用匿名原稿编号；原件名称、路径、哈希及历史对话索引仅保留在各自的本地资料库。

## 接入前需补齐

正式客户端扩展入口、项目与文件协议、模型网关能力、现有预览与导出方式。设计研究和独立核心规则可以先推进；这些接口未知时，不宣称已经接入现有产品。
