# 外部流程与 Panda 的结合

2026-10-12 复核官方入口及能力说明；细项来源见 `resources/sources/external-tools.json`。以下是方案选择与文档研究，未安装这些制作器，也未把它们的示例成品当作 Panda 实测结果。

## 借鉴哪些流程

| 来源 | 可借鉴的机制 | Panda 的适配 |
|---|---|---|
| [PPT Master](https://github.com/hugohe3/ppt-master) | 区分新建、模板提炼、已有稿编辑；Brand / Style / Layout / Deck 分层 | 将品牌身份、视觉表达、结构与成稿组合分别存储；先判断本次路线，不把外部多阶段审批照搬给用户 |
| [Microsoft Slide Master](https://support.microsoft.com/en-us/office/what-is-a-slide-master-b9abb2a0-7aef-4257-a14e-4329c904da54) | 母版及布局维护共享格式、字体与固定要素 | 客户上传模板时先识别锁定项与占位内容；品牌一致不等于所有页结构相同 |
| [PptxGenJS](https://gitbrent.github.io/PptxGenJS/docs/quick-start/) | 用代码建立文本、图片、图形并输出 PPTX | 无固定模板时，先试原生新稿；使用实际中文和空间图检验排字与裁切 |
| [pptx-automizer](https://github.com/singerla/pptx-automizer) | 复用现有幻灯片或对象，替换文本、图片与数据 | 已有公司品牌稿时，先试保留母版与稳定对象名的模板路线；复杂对象保真逐项验证 |
| [Marp CLI](https://github.com/marp-team/marp-cli) | Markdown/CSS 快速形成内容与演示稿 | 可选内容校样路线；常规 PPTX 为图片式，实验编辑模式另有条件，不能当可编辑 PPT 的默认交付 |

这些资源解决不同问题。PPT Master 是流程与工具集合；PptxGenJS 和 automizer 是制作候选；母版是文档结构；Marp 可辅助校样。无需一口气安装全部工具。

## 用已有包填补什么

Panda 原 PPT 包保留项目理解、叙事和室内设计资料关系；图片杂志包提供画面主次、负空间、文字角色与导出约束；动态网页包提供窄屏重排、图库、动效与减少动态的经验。共同底稿包含真实内容和品牌，各媒介保留自己的布局计划。

对来源脚本的实际阅读发现：杂志 render-pages 主要将 HTML 页面导出为图片，并不是自动设计引擎；网页 bundle-html 的内联能力有限，不能承诺任意站点都能成为离线单文件；网站 audit 脚本的首屏检查不能证明全页面交互与审美合格。接入时应补错误报告、完整滚动覆盖、键盘检查与实际成品复核。原包保存在本机登记的资料位置，未自动执行。

## 首个技术选择实验

用同一组真实材料做两条路线：A 从原生对象新建；B 在用户授权母版中填入并扩展。测试内容包括中文长标题、空间主图、两个方案对照、一张可读平面、一页编号材料、一次 Logo 更换及一次外部手改回传。

评估事实正确、文字/形状可编辑、中文字体、对象丢失、裁切、模板保真、局部改稿影响、生成和渲染耗时。审美需看同素材下的真实页面和用户具体反馈，不能用 GitHub 热度或库的宣称替代。

## 当前决定

先保留两个 PPT 后端适配位置，经过同素材试排再定首选；网页与图片后端各自实现。核心代码不依赖任一制作器，因此未来更换工具不会重写项目事实与设计库。

当前在 Codex 内实际制作演示文稿时仍遵循宿主 Presentations 技能所支持的工具；这里讨论的是 Panda 产品后续集成，不视作已经替换宿主工具。

接入时锁定实际版本。第三方代码、依赖、字体与素材分别记录；例如 PPT Master 的可选 PDF 转换依赖有独立许可，不能笼统把整条链称作同一许可证。当前仓库只保留自写分析与来源链接。
