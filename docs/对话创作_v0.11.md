# Panda 对话创作 v0.11

更新：2026-10-13。

界面只保留一个输入框：打字、上传图片和文件、接着聊。打开即用，项目在第一次发送时建立。模型选择、Skill 调用和文件制作在后台完成，使用者无需学习分步工作台。

## 这样开始

上传资料后直接说：

> 这是一套住宅设计，准备向业主汇报。先帮我看懂资料，再和我讨论该怎么讲。重点是家人的生活需求怎样一步步落到空间方案。

如果已经想清楚，也可以一次说明：

> 请根据这些资料制作一份给业主看的 PPT。图片要大，文字克制。先讲家庭需求，再讲空间安排和设计选择；没有依据的信息不要补写。

如果资料里含参考案例、Logo 或固定版面，可以在对话中说明用途，先讨论如何使用。当前新入口的附件统一保存为内容资料，还不会根据这句话自动改写资产角色、绑定 Logo 或锁定模板；这些绑定能力仍待实现。不要把口头理解当成已经执行的品牌约束，正式制作前需核对，不能承诺自动套入 Logo 或完整继承母版。

## 讨论、制作、改稿

| 想做的事 | 可以怎样说 | 预期动作 |
|---|---|---|
| 先了解资料 | “先看看这些资料，帮我梳理问题。” | 阅读可用内容、解释理解、补问；先不制作文件 |
| 校准方向 | “希望业主理解父母偶住时的空间安排，别只罗列效果图。” | 更新理解与表达方向 |
| 开始制作 | “按这个方向开始制作 PPT。” | 组织页面并生成文件 |
| 修改一页 | “第 3 页图片放大，文字只留两句。” | 修改指定一页，再生成更新文件 |
| 重做整套 | “按现在的家庭需求重新制作整套。” | 用当前要求重新编排 |
| 补一个格式 | “把当前页面导出成网页。” | 在页面有效时生成所需格式 |
| 只重新导出 | “重新导出。” | 保留内容，仅重新生成文件，不再次调用模型 |

缺少明确页码、需求有冲突或资料不足时，Panda 应先通过对话澄清。当前单页改稿一次只处理一页，不把“修改第 3 页”扩展成整套重写。讨论中的疑问与“先别做”也不应触发制作。

完成后，对话中显示结果卡。可下载 PPT、打开网页、查看逐页预览和保存图片。继续发消息即可提出修改。界面只展示当前内容对应的有效结果，旧文件仍保留在本机项目目录。

## 上传与历史

支持选择文件、拖放文件和粘贴图片。当前接收 PNG、JPG/JPEG、WEBP、TXT、Markdown、DOCX、PDF、PPTX、DWG、DXF；单文件最多 64 MB，一个项目最多 40 份资料。接收范围大于当前解析范围，原生 CAD、扫描 OCR 和完整母版解析尚未实现。

附件发送前可以移除。Enter 发送，Shift+Enter 换行。右上角的历史入口用于返回已有项目，新对话用于开始另一件事。新建不会删除资料；原有项目继续保存在本机。

发送后，相关说明、对话上下文、压缩图片和提取文本会按需交给配置的模型服务，并产生调用费用。原件与项目保存在本机，不自动上传到 GitHub。一句话触发整套制作时，后台可能先理解，再规划，因而包含多次模型调用。

## 技能怎样在后台衔接

对话是入口，专业工作仍需要明确分工：

1. 接收资料，记录来源与当前可读范围。
2. 按任务加载意图访谈、资料理解、案例推演和设计检查规则。
3. 模型根据用户要求提出“继续回复、开始制作、单页改稿、导出”的动作建议。
4. 服务端校验真实用户意图、页码、内容版本和可用版式，再执行相关步骤。
5. 本地制作器生成文件，返回结果与必要说明；下一轮继续沿用当前项目。

每条消息带独立请求编号。`POST /api/projects/:id/conversation` 开始处理，`GET /api/projects/:id/conversation/:requestId` 查询同一任务；重复查询或刷新不代表重新提交。付费阶段完成后先保存结果，再采用到项目。发生并发修改时保留候选，避免覆盖新内容。旧的分析、规划、编辑和导出接口仍保留给代码使用，界面不再暴露这些步骤。

后端仍需检查图片与文本是否实际送入模型、事实是否有证据、参考是否被误当作项目资产、修改是否越界。界面简化不改变这些质量要求。
