# 本地导出模块

`src/renderers/index.mjs` 提供 `renderProject({ project, projectDir, outputDir, formats })`。`formats` 接受 `pptx`、`web`、`images`，默认全部。每次使用一个新的空输出目录，避免覆盖已有成品。

返回 `{ files: [{ name, format }], slides: [{ id, preview }], warnings: [] }`。所有文件名和预览路径相对于输出目录。PPTX 中的文字为原生文本框，图片以独立对象嵌入。网页包含图片字节和样式，可离线打开并在窄屏重新排列。PNG 为 Artifact Tool 实际逐页渲染。

运行环境需要 `@oai/artifact-tool` 与 `sharp`。可以使用宿主已安装包，也可以通过 `PANDA_NODE_MODULES` 指向宿主提供的模块目录。源代码不记录开发机路径。测试集成部分另外使用 `jszip` 检查原生文本和字体声明。

默认画布为 1280 × 720，选择微软雅黑。宿主需要确认字体可用，或提供已确认的 `brand.fontFamily`。六类页面分别处理封面、主图、图文、对照、正文和图纸。文字太长时返回 `TEXT_OVERFLOW`，不会丢字或将正文压成不可读的小字。

导出前按保守字宽插入换行，避免常见中文闭合标点出现在新行开头或开括号留在行尾，同时保持英文词组中单词完整。该步骤只增加换行，保留原字符及已有段落。它属于排版预处理，不等同于操作系统完整的字体测量；宿主换字体后仍要看逐页渲染。

资源只读取项目目录中 `assets/安全编号.扩展名`。同时检查真实路径，拒绝路径穿越和指向外部的链接。图片须已标准化为 PNG/JPEG、单帧且方向正确。图片默认完整等比显示；明确设置 `slide.imageFit='cover'` 后普通照片才允许小幅裁切。图纸和 Logo 始终完整显示。渲染器不调用模型，不改造原图，也不解析原生 CAD。

`.private/` 保存逐页布局与渲染记录供复核，不列入用户输出清单。记录状态是“已渲染、待视觉复核”，不表示目标软件打开或完整产品验收。实际交付时仍需检查每页的预览、内容来源、中文换行、品牌和编辑范围。开发工作流应对最终 PPTX 使用 Presentations skill 的 finalization 检查；模块本身不依赖特定宿主的 Skill 安装路径。

导出的是自包含项目展示网页，没有线上发布行为。PNG 目前与 PPT 共用横版设计，还没有独立实现竖版杂志和印刷出血规范。
