# 核心代码契约 v0.1

这是零第三方依赖的 Node ESM 规则核心，不是已运行的Panda产品、模型代理或PPT生成器。最低 Node.js 22；`npm test` 调用内置 `node --test test/core.test.mjs`，无需 `npm install`。未安装 npm 的运行环境可直接执行该 Node 命令。

公共入口为 `src/core/index.mjs`。四个函数均为纯函数：不读写文件、不访问网络、不读取环境变量、不提交或取消服务任务、不修改传入对象。正常业务失败返回检查结果；缺字段、未知枚举、重复ID等契约错误抛出 `TypeError`，宿主必须处理，不能捕获后当作通过。

`examples/project.json` 是可直接传入接口的完整虚构数据。其产物不存在、服务尚未运行、所有验收未执行；研究卡的观察字段也只是测试结构示例。测试中的成功证据是人工构造的测试输入，不证明有真实PPT或渲染结果。

## 1. 项目与版本

`project` 包含：

| 字段 | 约定 |
|---|---|
| `project_id` | 非空项目ID，由宿主验证所属用户和访问权限 |
| `revision` | 非负安全整数；项目、任务取消/采用和依赖变更时递增，用于原子提交 |
| `versions` | 五个非空版本标识：`asset / content / brand / layout / permission`；只比较相等，不猜版本先后 |
| `permissions` | 操作名称到布尔值；例如 `image_outpaint: false`；缺失操作默认无授权 |
| `active_tasks` | 输出槽到当前任务ID，例如 `hero_image: task-2`；新任务替换同一输出槽后，旧任务不能采用 |

项目ID不等于认证。宿主须隔离用户、项目、原稿及研究库，确认输入内容的访问范围。五种版本不等于五个文件：Logo换版通常影响资产、品牌及项目修订号；撤回扩图影响权限及项目修订号。具体哪些版本递增由编排器统一决定。

任务和产物都带完整 `input_versions` 及非空、无重复的 `depends_on`。依赖只允许五种版本键，始终必须包含 `permission`。默认使用全部五种依赖；只有适配器能证明某维度不参与实际输入时才可省略该依赖，不能为避免过期检查而省略。输入快照仍必须保留全部五种版本。

## 2. `evaluateTaskAdoption({ project, task, result })`

检查服务结果是否有资格提交到本项目的当前候选状态；通过并不代表成品通过交付验收。

`task` 必需字段：`project_id / task_id / operation / output_slot / input_fingerprint / input_versions / depends_on / service_status / adoption_status / cancel_requested`。

`result` 可以是 `null`；成功采用时必须包含 `project_id / task_id / input_fingerprint / input_versions / artifact_ref`。返回值必须能绑定回原任务与原输入，不能只凭服务说“成功”就采用。`input_fingerprint` 是宿主计算的不可变输入指纹，核心只做比较，不计算文件哈希。`artifact_ref` 是宿主内部引用，不代表本函数验证过文件存在。

两组状态分开：

- `service_status`：`pending / running / succeeded / failed / outcome_unknown / canceled`。这是上游真实执行结果，核心原样返回；本地撤销不能把它改成 `canceled`。
- `adoption_status`：`pending / adopted / rejected / canceled / superseded`。终态不得复活。`pending` 可以等待上游核实；`adopted` 只在宿主成功提交后设置。

采用条件同时满足：同项目、任务仍是该输出槽的当前任务、当前仍授权该操作、任务未取消、采用状态仍为 `pending`、服务为 `succeeded`、依赖版本未变化、结果绑定完全一致。

主要行为：

| 情况 | 采用结论与后续建议 |
|---|---|
| 超时且可能已受理 | 保持 `outcome_unknown`；建议查询原任务；不准发起新请求 |
| 撤回权限 | 采用状态 `rejected`；停止本地队列和重试；上游可能在执行时建议按能力申请取消 |
| 用户取消 | 采用状态 `canceled`；迟到成功结果也不得进入新稿；上游状态独立保留 |
| 依赖换版或同槽出现新任务 | `superseded`；旧结果保留为未采用结果 |
| 服务明确失败 | `rejected`；可检查错误；本函数不授予重试授权 |
| 任务或结果属于其他项目、指纹错配 | `rejected`；无提交令牌；外项目任务不会产生上游查询或取消建议 |
| 已采用结果重复回调 | 不再次采用；不产生新的提交令牌 |

返回 `can_adopt / service_status / adoption_status / reason_codes / stale_dependencies / next_actions / may_submit_new_request / commit_guard`。`may_submit_new_request` 始终为 `false`，因为该函数不负责预算和重试授权。即使提供方支持幂等键，也应在独立调度策略中核验，撤回授权后不得借幂等重发恢复任务。

`next_actions` 是明确的建议值，绝不是已经执行的操作。取消请求不代表取消成功或停止计费。即使本地采用决定已进入终态，上游仍是 `outcome_unknown` 时也继续建议查询原任务，但绝不恢复采用或重发。宿主应保留任务ID、错误、服务响应和费用结果；本骨架没有计费或队列实现。

### 原子提交是宿主责任

纯函数无法阻止检查与写入之间发生竞态。`can_adopt: true` 时返回 `commit_guard`，至少绑定项目修订号、当前输出槽任务ID、任务采用状态、取消标记、服务状态、输入版本和指纹。

宿主必须在同一事务中比较这些条件，再写入候选结果并将任务标记为 `adopted`、递增项目修订号。令牌内 `input_versions` 绑定原任务快照，和项目当前版本比较时按随附 `depends_on` 取实际依赖；项目修订号仍须整体相等。任何条件变化都应拒绝提交，并用最新项目状态重新检查；不能先无条件写文件、再事后核验令牌。取消、换Logo、权限撤回和用户重传PPT也必须参与这套事务及版本更新。

`rejected / canceled / superseded` 等决定也应由宿主持久化，防止稍后重新授权时意外复活旧任务。保留旧文件与原始服务记录，不能以过期为由自动删除用户原件。

## 3. `selectReferenceCandidates({ page_task, cards, limit = 5 })`

这是透明的标签候选筛选，不是语义设计判断、版权授权器或素材复制器。

`page_task` 包含 `project_id / page_task_id / medium / task_tags / text_density / image_shapes / locked_elements / require_editable`。媒介为 `ppt / web / images`；文字密度为 `low / medium / high`；任务标签与图像形状使用精确字符串匹配。

原生 `cards` 契约见示例：

- `scope` 必须是显式的 `public` 或指定 `project_id` 的 `project`；`public` 表示宿主已确认可在当前资料范围用于研究，不表示可以复制成品素材。
- `source` 带来源ID、具体页或图片定位及 `observed / unreviewed`。未实际观察的卡不能成为本函数候选。
- `rights.study` 为 `allowed / unknown / forbidden`；`rights.reproduce` 为 `licensed / unknown / forbidden`，后者不参与复制授权。
- `media / task_tags / text_densities / image_shapes` 是结构标签。`design_logic` 为可读设计说明，不参与自然语言推断。
- `requires_changes` 是明确已知的版面变化项；`null` 表示还未核验，`[]` 才表示已标注没有必需变化。与锁定元素冲突的卡排除。
- `editable_strategy` 可为 `true / false / 'unknown'`；已知无法满足可编辑要求的卡排除，未知者仅作带待核验说明的研究候选。

先过滤项目范围、研究使用权限、观察状态、媒介、已知品牌冲突和编辑性冲突，再按任务标签、明确密度标签和图像结构标签给透明分值。至少有一项任务标签匹配；不因颜色相似或卡片知名而强行返回。并列按卡ID稳定排序，没有适用卡就返回空列表。

返回 `candidates`（卡ID、理由、分值、待复核项）与 `excluded`（卡ID、排除原因），不返回素材文件、模板对象或复制操作。每个候选和总结果均带 `asset_copy_authorized: false`，即使研究卡写着 `reproduce: licensed` 也不改变；生产资产需另走项目授权与资源契约。

### 对接资料索引：`mapResearchCard(card, { scope })`

支持 `resources/design-library/index.json` 的记录字段：`id / title / source_id / source_page / task_tags / media_tags / suitable_for / avoid / review_status / rights / card_path`。

- `source_page` 为1起算正整数；独立图片为 `null`。
- `actual_preview_viewed / actual_image_viewed` 映射为已观察，其余状态保持未观察。
- `research_reference_only_reuse_not_verified` 仅映射为可研究、复制权限未知。
- `suitable_for / avoid` 保留为可读方法与限制，不从“密集说明”“横图”等自然语言推断精确密度、图形或锁定项兼容性。
- 索引没有提供的图形/密度标签为空，`requires_changes: null`，`editable_strategy: 'unknown'`；候选必须继续复核。
- `scope` 无默认值，缺省抛错。宿主应先限制检索资料范围，再为获准卡逐条映射；不能把整库默认标为 `public`。
- `card_path` 不转换为可复制素材路径，也不会出现在筛选结果里。

## 4. `evaluateDelivery({ project, artifact, evidence })`

逐个产物检查，不能以一个成品通过代表整套所有输出通过。

`artifact` 含 `project_id / artifact_id / version / format / input_versions / depends_on / unit_ids / exists / editable_required`。`unit_ids` 为非空稳定单元ID（PPT页、网页检查区段/视口或图片），不能只依赖可能因重排改变的页码。`exists` 必须来自宿主实际文件检查，本函数不访问文件系统。

四类证据分开：

| 证据 | 可通过的必要内容 |
|---|---|
| `render` | `status: passed`、`method: actual_render`、运行ID、工具ID、非空渲染输出引用、覆盖全部单元 |
| `technical` | `status: passed`、运行ID、工具ID、覆盖全部单元、明确 `issues` 数组；要求可编辑时须有 `native_editable: true` |
| `visual` | `status: passed`、复核ID、复核者、当前渲染运行ID、覆盖全部单元、明确 `issues` 数组 |
| `user` | `not_obtained / approved / changes_requested`；后两者必须带当前产物绑定、用户决定出处和涉及单元 |

成功证据必须带同一 `project_id / artifact_id / artifact_version` 与 `checked_units`。视觉复核必须绑定当前渲染的 `run_id`，不能用旧预览的好评给新版放行。任一 `blocking` 问题都会阻止制作完成，不可用总评分抵消。静态检查、文件可打开、模型自评都不能代替 `actual_render`。

没有执行时使用 `{ status: 'not_run' }`，用户使用 `{ status: 'not_obtained' }`；不要填伪造的通过记录。合法状态、必要字段及测试成功结构见 `test/core.test.mjs` 的 `reviewed()` 构造器；该构造器仅供测试。

返回值含义：

- `production_complete`：产物存在、依赖当前、真实渲染、技术和视觉复核全部通过。
- `ready_for_delivery`：制作检查通过，且当前版本没有已绑定的用户改稿要求。未获得用户认可本身不阻止交付候选文件。
- `user_approved`：有覆盖该产物全部单元、绑定当前版本的明确用户证据。局部批准不会扩大为整本批准。
- `status`：`needs_work / ready_for_delivery / changes_requested / accepted`；只有制作通过且用户确实认可才为 `accepted`。
- `checks` 保留提交方报告的状态；`verified_checks` 表示对应证据契约是否通过。`blockers` 与 `acceptance_issues` 列具体问题；旧用户意见不会套到不同产物版本。

`production_complete: true` 只说明传入证据满足本契约，不证明调用方没有伪造证据。可信适配器负责实际文件检查、渲染、预览留存和用户记录；不得让生成模型自行填“通过”后直接调用此函数完成验收。

## 当前边界

未实现账号认证、持久化、事务数据库、任务队列、真实供应商查询/取消、预算、PPT读写、PowerPoint渲染、网页托管或模型调用；未实现手改PPT内容比对与ID映射恢复。这里提供可测试的判断与输入输出边界，供已有Panda宿主接入。真实渲染、原生可编辑性、手机体验与用户认可仍需用实际项目验证。
